AI Product · Mini App · 2026.09

把自己做成用户：秋招雷达 0→1 复盘

起点是一个具体的问题：环境设计背景想投 AI / 产品 / 交互岗，几千条校招 JD 里逐条翻找对口岗位，耗时且低效。这个产品从开发者本人的真实投递需求出发——我自己是第一个用户，需求来自实际投递过程。

最重要的产品决策是不做信息搬运，做匹配判断。市面上的汇总表只回答"有哪些岗"，而求职者真正的问题是"哪些值得投"。为此我设计了 S / A / B1 / B2 / C / D 六档评价体系——它是一套判断标准，可复用、可解释，也可迁移到其他垂直领域的信息筛选产品。

开发上采用「我出需求与验收标准，AI 出码」的分工。每一版都做真机全流程测试，记录卡点与低频功能，纳入下一版迭代。最主要的经验是功能优先级应由真实使用决定——v1 只做了岗位列表，而实际高频操作是"复制网申信息"和"检查截止时间"，快捷复制与今日聚焦因此被排进后续版本。

Agent · CAD / Blender · 2026.09

Agent 驱动 CAD-Blender 建模：问题与解法

起点是环境设计流程中的固定环节：CAD 里画完平面图，切到 Blender 里手工翻模，耗时半天。第一次尝试是让 Agent「一句话出模型」——直接失败：它会"幻想"出图纸上不存在的墙，尺寸也全凭感觉。结论是明确的：专业生产软件不能纯靠对话驱动，幻觉落在建模里就是灾难。

可行的做法是把管线拆成可验证的步骤：ezdxf 提取墙体门窗 → 桥接进程驱动 Blender 生成 → 校验脚本核对面积与尺寸 → 导出 .blend 与 .glb。每一步都有可检查的中间产物，Agent 出错可以当场定位。最早写成的反而是环境自检脚本——第一次导出时模型大了 1000 倍，因为 CAD 用毫米、Blender 用米。

最后一步是沉淀：跑通之后，把流程封装成 Skill 包（手册 + 工具 + 实战示例），其他 Agent 安装后可直接复用。这个项目让我确认的一点：Agent 的上限不取决于模型多聪明，取决于人给它多大的可验证空间。

Digital Twin · Factory HUD · 2026.09

厂区孪生的指标取舍与交互设计

做完社区孪生再做厂区，才体会到场景决定指标：社区看的是生活状态（人流、安防、环境），厂区看的是生产状态（在线率、产量、能耗、告警）——KPI 卡只保留最关键的四张，其余一律不展示。

设计上有两个关键决策：一是告警分级，红黄两级 + 时间戳排序，优先级一目了然；二是快捷视角——鸟瞰 / 生产 / 仓储 / 动力 / 办公五个预设，一次点击相机直接飞行到位。厂区场景下，管理者需要的是尽快定位到目标建筑，而不是自由旋转视角。

数据目前是模拟的，但架构是完整的：模拟数据模块换成 WebSocket 即可接入真实数据。先立框架再接数据——演示先行，反馈来得更早，接口也定得更准。

AI Video · Workflow · 2026

用 ComfyUI 串 MiniMax 与 Seedance 的一点心得

目标很明确：设计意向图要动起来，而不是随便生成一段酷炫画面。所以流程固定成「静帧定风格 → 图生视频补运动 → 超分放大 → 剪辑收束」。

MiniMax H3 更适合氛围和镜头语言，Seedance 2.0 在结构稳定性上更稳。关键帧给足（透视、光影、主体占比），运动幅度先小后大；一次只改一个变量，否则很容易整段崩。

后期一定要超分再剪。原片噪点和抖动放大后很脏；剪辑时宁可短、宁可慢，也不要连续快切——空间类影像的说服力来自「能看清场所」，不是转场炫技。

Digital Twin · Three.js · 2026

把空间搬进浏览器：数字孪生小实验复盘

云璟天悦这个实验想回答：社区的「活数据」能不能让人一眼看懂。场景用 Three.js 搭可旋转模型，看板用 ECharts 叠能耗、电梯、安防、车流与环境监测。

几个教训：模型面数要克制，装饰细节放到贴图里；数据图例颜色跟三维材质别打架，否则看板像贴纸；事件流要限速滚动，信息密度高不等于一直闪。

最出效果的是「一键进室内」——社区层跳到全屋水电孪生，同一套交互语言。孪生的价值不在炫模型，而在让人从总体切到细节，路径不断。

Interactive Web · Prototype · 2026

交互原型：3D 全屋工坊与像素画板

全屋工坊只想解决三件事：换材质、摆家具、切光照。Three.js + OrbitControls，控制面板保持三列以内，改完立刻在场景里看到结果——「所见即所调」比任何说明都有效。

像素画板反着来：8-bit 网格、调色板、撤销栈、导出 PNG。撤销用简单命令模式就够；导出前把画布放大最近邻采样，像素才不会糊。

两者都是纯前端、打开即玩。设计课上大家点开链接就能上手，比发一堆渲染图更能说明「空间可以被操作」。原型不是成品，但它是把想法递给别人的最短路径。

User Research · Methodology · 2026

从场地走访到方案推演：一套可复用的用户研究方法

青山村不是从一张漂亮平面开始的。先走完整片老村委：哪几户还住人，哪面墙被海风掏空了，哪条巷子傍晚还有人坐着聊天。这套「走访-观察-记录」的方法，放到产品里就是用户研究。

最后留下三条原则：不铲平记忆（尊重用户已有的使用习惯）、把场景重新接上（让关键路径在体验里连续）、低干预设计（能复用的不重造，能借势的不硬推）。

推演阶段改了五轮平面。第三轮曾想做大广场，现场走完就否了——尺度不对，人不会在那停留。产品方案也一样：不是坐在工位想出来的，是在用户场景里反复走、反复看里长出来的。
